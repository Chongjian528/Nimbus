# Nimbus — Soft ERP & CRM Admin Template

A soft, pastel admin dashboard built with plain **HTML, CSS and JavaScript** — no build step, no framework.
39 pages covering CRM, sales, inventory, finance, HR and workspace tools, fully responsive (phone → desktop) with light and dark themes.

## Quick start

Everything — fonts, icons, charts, drag and drop — ships in `assets/plugins/`, so the template works fully **offline**. Double-click `index.html`, or serve the folder:

```bash
python -m http.server 5173
```

Then visit <http://localhost:5173>.

## Structure

```
assets/
  css/app.css    design tokens (light + dark), layout, components, responsive rules
  js/app.js      app shell (sidebar, topbar, footer), theme, dropdowns, modals, tabs,
                 toasts, form validation, command palette, data tables, chart helper
  js/data.js     seeded demo data (window.DB) — replace with your API
  img/favicon.svg
  plugins/       third-party files, bundled for offline use (see Libraries)
*.html           one file per page; each page renders only its own content
```

The sidebar, topbar and footer are generated by `app.js`, so navigation lives in one place: edit the `NAV` array in `assets/js/app.js` to add, remove or rename menu items.

## Customizing

- **Colors, radius, shadows, fonts** — edit the tokens at the top of `assets/css/app.css` (`:root` for light, `[data-theme="dark"]` for dark). Every text/background pair was checked for WCAG AA contrast; re-check if you change them.
- **Brand** — change the name and the `BRAND_SVG` logo in `app.js`, and `assets/img/favicon.svg`.
- **Data** — every page reads from `window.DB` in `data.js`. Swap those arrays for `fetch()` calls to your backend.
- **New page** — copy any page (e.g. `customers.html`), keep the `<head>` and app shell, replace what’s inside `<main>`, then add it to `NAV`.

### Reusable helpers (`window.App`)

| Helper | Use |
|---|---|
| `App.table(el, { data, columns, … })` | Searchable, sortable, paginated table with row selection; turns into cards on phones |
| `App.chart(el, apexOptions)` | ApexCharts with theme-aware colors (`'--chart-1'` tokens) and an automatic “View data table” |
| `App.toast(msg, { type, title })` | Toast notifications |
| `App.confirm({ title, text, confirm })` | Promise-based confirmation dialog |
| `data-validate` on a `<form>` | Native validation with inline messages; fires a `valid` event with the form data |
| `data-modal="#id"` / `data-modal-close` | Open/close native `<dialog>` modals |
| `data-dropdown`, `role="tab"`, `data-segmented` | Dropdown menus, tabs and segmented controls — no extra JS needed |

## Libraries (bundled in `assets/plugins/`)

| Folder | Library | Version | License | Used by |
|---|---|---|---|---|
| `apexcharts/` | [ApexCharts](https://apexcharts.com) | 4.7.0 | MIT | pages with charts |
| `sortablejs/` | [SortableJS](https://sortablejs.github.io/Sortable/) | 1.15.7 | MIT | `deals.html`, `tasks.html` |
| `phosphor-icons/` | [Phosphor Icons](https://phosphoricons.com) (regular + fill) | 2.1.2 | MIT | every page |
| `plus-jakarta-sans/` | [Plus Jakarta Sans](https://fonts.google.com/specimen/Plus+Jakarta+Sans) variable font, via Fontsource | 5.3.0 | SIL OFL 1.1 | every page |

Each folder keeps its license file. The files are unmodified copies from npm (via jsDelivr), except that the Phosphor `@font-face` rules point only at the bundled `.woff2` files — the `.woff`/`.ttf`/`.svg` fallbacks for legacy browsers were left out. To update a library, replace its folder with the newer files.

**Why ApexCharts is pinned to 4.7.0:** it is the last MIT-licensed release. From version 5 onwards ApexCharts uses a dual license (free only for organizations under US$2M annual revenue, and an OEM license for interactive charts in products used by other people). Read the new license before upgrading.

## Accessibility & responsiveness

- Keyboard support throughout: skip link, visible focus rings, arrow keys in tabs and menus, `Ctrl/⌘ + K` or `/` for search.
- Native `<dialog>`, `<details>`, `<progress>` and form controls; icons are hidden from screen readers.
- Drag-and-drop boards also let you change a card’s column from its edit dialog.
- Respects `prefers-reduced-motion`, plus a **Reduce motion** switch in Settings → Appearance.
- Phones get an off-canvas menu, card-style tables, bottom-sheet modals and single-pane chat/mail; tested down to 375 px.

Requires a modern evergreen browser (uses `:has()`, `color-mix()`, `<dialog>` and `dvh` units).
